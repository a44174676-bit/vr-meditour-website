## 공식 기준과 검증 한계

사용자가 지정한 「VR MEDI TOUR & HOME 유학생 전용 랜딩페이지 PRD v1.0」을 공식 개발 기준으로 삼는다. **하지만 이번 메시지에는 읽을 수 있는 원본 첨부/본문/다운로드 ID가 전달되지 않았다.** 저장소 및 `/workspace/library-files`, `/workspace/shared/downloads`, `/workspace/scratch`에서 재검색했으나 파일이 없다. 사용자에게 재첨부를 요청했다.

따라서 FR 번호에 기능명을 임의로 연결하거나 P0 완료율을 계산하지 않는다. **원본 요구사항 확인: 0/12, 원본 충족률: 산정 불가**. 이것은 구현 완료율 0%라는 뜻이 아니다. 아래 FR 표는 원본 수령 후 채워야 하는 정직한 추적표이며, 그 다음 표가 현재 실제 코드 상태다.

판정 정의:
- 구현 완료: 합의된 범위의 코드와 해당 기능 검증이 모두 존재.
- 부분 구현: UI/일부 로직만 있으며 운영 연결/보안/검증 등이 남음.
- 미구현: 해당 기능 코드 없음.
- 검증 불가: 공식 요구사항 또는 검증 환경/증거를 확보하지 못함.

## 이번 독립 보완 사항

### 관리자 모의 화면

개발 URL: `http://127.0.0.1:8080/dev-tools/study-korea-admin/` (저장소 루트 정적 서버 실행 시). 운영 페이지 경로가 아니며 **dist에 포함되지 않는다**. 모의 역할 선택은 인증이 아니고 모든 가상 데이터는 브라우저 소스에서 볼 수 있다. 실제 개인정보를 넣거나 이를 보안 경계로 사용하면 안 된다.

- 학생/기관별 가상 접수 4개, 상태 필터, 유형 필터, 담당자 변경, 메모리 변경 이력.
- 제안 상태: new → reviewing → waiting/completed/closed. waiting→reviewing/closed, completed→reviewing/closed, closed는 종결. 원본 PRD 확인 후 확정.
- 담당자는 활성 계정이며 같은 문의 유형 역할이어야 함. 변경 배정은 총괄 관리자만 가능. 개별 담당자는 자신에게 배정된 해당 유형 문의만 표시.
- 미인증/비활성/다른 유형/배정되지 않은 역할 거절 모델. 동시 수정은 version 비교로 충돌 검출.
- 한·베 UI, 모바일 카드 레이아웃. 실데이터 입력 필드/네트워크 저장/브라우저 영구 저장 없음. 새로고침하면 모두 초기화.
- 운영에서는 서버가 세션 서명/만료/역할/배정을 검증해야 한다. 클라이언트 모델 테스트는 실제 접근제어 구현을 대체하지 않는다.

### 데이터 모델/보유/중복 설계

`docs/study-korea-data-model.sql`은 **실행하지 않은 검토용 SQL**이다. 전용 `student_korea_private` schema와 문의·관리자 역할·감사·알림 outbox를 제안한다. 각 테이블에 RLS+FORCE RLS, PUBLIC 권한 회수, 허용 정책/권한 부여는 없음. Auth 제공자 결정 전에는 기본 거절 상태로 둔다. 서비스 superuser/BYPASSRLS 키는 별도 통제가 필요하다.

- 현재 필수/선택은 원본 미수신으로 기존 메시지 기준을 유지. 학생/기관 필드 혼입 방지 CHECK, 길이/열거값, 민감 식별번호 필드 없음.
- receipt ID는 공개 열람 토큰이 아님. `submission_id` UNIQUE + canonical payload HMAC를 원자적으로 비교: 동일 ID/동일 내용은 기존 접수번호, 동일 ID/다른 내용은 409.
- 문의 + outbox는 같은 트랜잭션, DB commit 이후만 성공. 관리자 알림에는 개인정보 본문 제외.
- 상태 전환/배정 역할 검사/`WHERE version=expected` 갱신/감사 기록은 운영 수신기 또는 DB 함수 한 트랜잭션에서 처리. 초안 SQL만으로 이 검사를 보장하지 않음.
- 정책 버전/동의시각/보유정책 버전/삭제예정일 필수. 보유기간 숫자는 법인 승인 전 미정. 종료 상태가 곧 파기 완료인 것은 아님.
- 승인된 일정의 파기 작업은 문의·outbox·다운로드 사본을 처리하고 감사 로그는 별도 승인 기간 적용. 백업 만료/복원 후 재삭제와 삭제 요청 본인 확인 절차 필요.
- 현재 페이지 재시도 ID는 메모리 한정. 새로고침/여러 탭 중복은 아직 방지하지 못함. 운영에서는 개인정보 없이 만료되는 제출 토큰을 도입할지 결정. 연락처가 같다는 이유만으로 서로 다른 상담을 자동 병합하지 않음.

## publish='.' 위험과 개선

이전 설정은 저장소 전체를 정적 게시 후보로 삼아 docs/tests/서버 코드/향후 내부자료가 공개될 위험이 있다. robots/noindex/숨긴 링크는 접근제어가 아니다.

이번 변경:
1. `netlify.toml`: `command = "node scripts/build-public.cjs"`, `publish = "dist"`. 함수 디렉터리와 기존 리다이렉트·function included_files는 유지.
2. `scripts/public-files.json`: 검토된 공개 파일 361개를 정확한 경로로 열거. 디렉터리 전체 복사를 하지 않아 새 내부 파일이 자동 공개되지 않음.
3. 빌드: 경로 이탈·심볼릭 링크·내부 경로·일부 비밀키 패턴 검증 후 dist 생성. docs/tests/dev-tools/netlify/scripts/숨김 파일/백엔드는 산출물에 없음. 패턴 검사는 모든 비밀정보 탐지를 보장하지 않으므로 코드 리뷰/전용 secret scan 필요.
4. 기존 공개 페이지·CSS·JS·이미지·오디오를 동일 상대 경로/동일 바이트로 복사. 의료마이데이터 함수의 source included_files는 그대로 남음. `_redirects`도 복사.
5. 별도 Vite 소스 프로젝트 `settlement-ai-system`은 게시 목록에서 제외: 홈페이지 연결/배포 설정에서 현재 라우트를 찾지 못했으며, 필요 시 별도 정상 빌드 절차로 검토해야 함. 기존 AI/의료/관광 서비스 소스는 변경 없음.

주의: 향후 공개 파일을 추가할 때 manifest도 리뷰해야 함. 배포 전 Netlify Node 런타임·UI의 build override·함수 번들 included_files·전체 리다이렉트·기존 공개 경로를 테스트 환경에서 검증. 이번 작업은 로컬 빌드만 실행했으며 운영 설정을 활성화하거나 배포하지 않았다.
