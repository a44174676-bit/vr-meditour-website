## 1. 현재 실제 동작
- `/renewal-preview/partners/`: 기관명·도시·협력분야·미팅방식을 브라우저에서 조합하여 문안을 표시합니다. `복사` 또는 `mailto:`로 사용자가 직접 이메일 앱을 열어 발송합니다.
- 서버에 제휴 요청서를 저장하거나 실제 메일 발송을 완료했다고 표시하지 않습니다.
- `/edu/`의 초기 Netlify 폼은 자동 수집 대상에서 제외되었고 제출 버튼은 비활성화 상태입니다.
- 연결 Gmail 계정이 대표 회사 주소 `info@vr-meditour.com`와 일치하지 않으므로 이 주소의 수신/알림/권한은 아직 미확인 상태입니다.

## 3. 문의 처리 상태 모델 (개인정보 없는 합성 데이터로만 QA)
접수됨(Received) → 확인중(Triage) → 담당자 배정(Assigned) → 협의중(In discussion) → 종료(Closed)
대안 상태: 보류(On hold), 중복(Duplicate), 삭제 처리(Erased).
각 실제 케이스에는 ID, 접수시각, 문의유형, 업무 담당자, 후속 조치 예정일, 상태, 보관종료일을 기록하되 **승인된 내부 시스템에서만** 저장합니다.
Github 정적 저장소·공개 HTML·브라우저 URL/쿼리 문자열에 상담자 정보 기록 금지.

## 4. 승인된 후의 구현 및 검증 순서
1. 개인정보처리방침 개정 확정(현재 `/public/privacy-policy.html`은 법률 검토 전 초안).
2. Netlify 프로젝트 접근/서버 보안설정/폼 알림/보관 정책 확인.
3. 유학/제휴와 의료관광·여행 폼을 **서로 다른 컬렉션**으로 정의. 환자·건강정보는 이 일반 B2B 폼으로 수집하지 않음.
4. 개인정보 고지/동의 UI 및 서버 측 유효성 검증, 스팸 방지, 최소 수집 구현.
5. 개인정보 없는 `TEST_COMPANY_01`, `test@example.invalid` 같은 합성 데이터로 접수→회사 관리자 알림→담당자 처리→삭제 테스트.
6. 접수자에게 실제 자동 회신 여부를 확인한 뒤에만 사용자에게 '접수 완료' 표시.
7. 승인한 서버 설정과 검수 결과를 기록하고, 배포 전 법인 대표 승인.
8. 5개 언어 고지를 전문가가 점검한 뒤 상용화.
