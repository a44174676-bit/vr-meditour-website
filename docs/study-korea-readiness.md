## 4. 접수 저장 방식 비교 및 권장안

| 항목 | Netlify Forms | Netlify Function + 관리형 DB/Auth |
| --- | --- | --- |
| 초기 개발 | 정적 form 탐지·등록·제출 처리로 간단 | DB/인증/권한/API/운영 작업 필요 |
| 두 문의 구분 | 별도 form 이름 | 종류별 테이블 또는 종류/담당 권한으로 분리 |
| 관리자 접근 | Netlify 팀/프로젝트 권한으로 대시보드 접근; 역할별 세분화는 계정 플랜 확인 | 업무별 역할·담당자 범위·MFA·감사 로그를 직접 구현 |
| 개인정보 위치 | 제공자 처리지역·이전·약관 확인 필요 | 승인한 DB 리전 선택; 인증/메일/백업의 지역도 별도 확인 |
| 보유/삭제 | 대시보드/API 삭제 작업과 보존 정책 검증 필요 | `delete_after`와 예약 파기, 백업 복원 시 재삭제 구현 가능 |
| 중복/상태/알림 | 자체 워크플로 설계에 제약; 추가 함수가 필요할 수 있음 | 유일키·트랜잭션·outbox로 저장/알림 일관성 확보 |
| 스팸 | 제공 기능/요금제 범위 확인 + 자체 대책 | 게이트웨이/분산 limiter/필요 시 봇 챌린지 구성 |
| 비용/운영 | 낮은 개발비, 제출량/플랜/팀 접근에 따른 비용 | 개발비 높음, 권한·수명주기 통제 용이 |

**권장: 기존 Netlify 함수 + 별도 관리형 PostgreSQL 및 Auth(예: 승인 후 Supabase 등 선정).** 학생과 B2B 문의를 명확히 분리하고 관리자 권한/자동 파기/접수-알림 일관성이 필요하기 때문이다. 제공자나 리전은 아직 선정·생성·연결하지 않았다. 기존 검증 함수에서 승인된 수신기를 호출하는 계약을 유지하거나, 추후 서버 내부 DB 저장 모듈로 교체할 수 있다.

Netlify Forms는 소규모 단기 운영이고 프로젝트 관리자 전원이 상담 데이터를 볼 권한이 있으며 보유기간/국외이전 조건을 충족할 때 대안이다. 관리자 권한·계약/보존 조건이 맞는지 확인하지 않고 Forms를 즉시 켜지 않는다. Netlify Forms와 자체 DB에 동시에 저장하는 이중 수집은 피한다.

## 5. 권장 구현 설계 (아직 구현하지 않음)

### 저장 및 신청 응답

1. 브라우저 → 동일 출처 HTTPS Netlify 함수 → 서버 입력 검증/분산 rate limit/봇 검증 → 승인된 DB 수신기.
2. 수신기는 토큰을 검증하고 동일 `submission_id`/payload hash 재시도는 기존 접수번호를 반환한다. 다른 payload의 동일 ID는 409로 거절한다. 원자적 unique constraint를 적용한다.
3. 트랜잭션 안에서 문의·정책 버전/동의시각·알림 outbox를 함께 저장한다. 트랜잭션 커밋 이후에만 접수 성공을 응답한다.
4. 알림 실패는 접수 성공을 취소하지 않는다. outbox 재시도/백오프/실패 큐/관리자 경보로 관리한다. 중복 알림도 event ID로 방지한다.
5. 고객 화면에 접수번호를 표시한다. 학생은 이메일을 수집하지 않으므로 이메일 확인을 약속하지 않는다. Zalo/문자 자동 발송은 별도 서비스·동의·비용 승인 전 구현하지 않는다. B2B 접수 이메일은 승인된 메일 발송자와 목적 범위에서만 사용한다.
6. 관리자 알림에는 문의 유형·접수번호·시각·로그인 필요한 관리자 URL만 포함한다. 이름/연락처/문의 본문을 이메일이나 메신저에 복제하지 않는다.

데이터 모델 제안: `student_inquiries`와 `partner_inquiries`(각 필수 필드, internal UUID, receipt ID, submission ID/hash, locale, policy version, consent timestamp, received_at, status, assigned_to, delete_after), `admin_roles`, `inquiry_audit`, `notification_outbox`. 공개 순번 대신 추측하기 어려운 접수번호 사용. 접수번호 자체를 열람 권한으로 사용하지 않는다.

### 관리자 인증·권한

- 공개 회원가입 없는 초대형 관리자 계정, MFA 필수, 퇴사/역할 변경 시 즉시 권한 철회.
- 로그인 세션/JWT의 서명·issuer·audience·만료와 서버의 admin 역할을 매 요청마다 확인. 클라이언트 role/localStorage만 신뢰하지 않는다.
- `counselor`: 배정된 학생 상담, `partnership_manager`: 배정된 기관 문의, `privacy_admin`: 파기/권한 승인. 모두 관리자 계정이며 일반 사용자 접근 불가. 내보내기는 별도 권한과 감사 기록.
- DB RLS/서버 최소권한으로 비로그인/일반 사용자 직접 조회 차단. 서비스 키는 서버 전용; RLS 우회키로 처리할 때는 함수의 역할/행 단위 검사를 생략하지 않는다.
- 관리자 API는 목록/상세/갱신/삭제 모두 개별 권한 검사, no-store, 데이터 최소 응답, 문자열 안전 렌더링, CSV 수식 주입 방지. 쿠키 인증이면 HttpOnly/Secure/SameSite와 CSRF 방어.
- 로그인 시도 제한, 세션 만료/강제 로그아웃, 조회/변경/내보내기/삭제 감사 로그. 감사 로그에는 상담 본문을 기록하지 않는다.

### 개인정보 최소수집·보존·삭제

- 현 PRD 필수 필드만 수집. 첨부·여권·외국인등록번호·건강정보·생년월일·주소 추가 금지. 자유입력에 민감정보를 쓰지 않도록 안내하고 운영자가 발견하면 제한된 절차로 삭제/마스킹.
- B2B의 이메일+전화와 학생 이름/문의내용의 필수성은 법인 검토 시 재평가; 사용자 필수 요구사항은 임의 변경하지 않음. 단순 알림을 위해 학생 이메일을 추가하지 않는다.
- 보유기간은 **미확정**. 학생/기관 문의 각각 목적·상담 종료 기준·보유기간·법적 예외를 승인하고 `delete_after`로 계산한다. 30/90/365일 같은 임의 수치를 운영값으로 넣지 않는다.
- 예약 파기, 관련 outbox/내보내기 파일 삭제, 백업 만료와 복원 후 삭제 재적용, 요청자 본인 확인 및 삭제 처리 증적. 증적/중복방지용 해시도 재식별 가능성을 평가하고 최소 기간만 보유.
- 개인정보 처리방침·동의 버전별 원문 보존, 정책 변경 시 재동의 필요 여부 검토. 미성년 학생/보호자 대리 신청의 적법한 동의 절차를 법인이 정한다.
- 위탁사/리전/하위처리자/국외이전/백업 위치를 확인하고 필요한 고지·계약·동의를 승인한다. 전송 TLS와 저장 암호화, 키 교체·접근감사·백업 복구 검증.

### 스팸·오류·운영

- 현재 허니팟/Origin/크기/입력 검증은 기본 방어일 뿐이다. 게이트웨이 또는 공유 저장소 기반 rate limit, 연락처/요청 단위 남용 탐지, 필요 시 서버 검증하는 봇 챌린지 추가. 공유 토큰 전역 한도만 쓰면 공격자가 전체 접수를 막을 수 있으므로 사용자별/전체 한도를 조합.
- IP는 프록시가 보장하는 값만 사용하고 짧은 기간의 키드 해시 등으로 최소 처리. 학생 공용 네트워크의 오탐을 고려한다.
- 400/403/409/413/415/429/502/503을 구분, 429는 재시도 안내/Retry-After. 타임아웃 후 같은 ID 재시도로 중복 저장 방지. 현재 클라이언트는 일반 실패 안내만 제공하므로 상태별 안내는 향후 구현 대상.
- 재시도 ID는 현재 페이지 메모리에서만 유지된다. 새로고침/언어 변경 후 재전송의 중복 방지 범위는 운영 구현에서 개선 필요. 개인정보를 브라우저 영구 저장하는 방식은 피한다.
- DB 연결/정책 문제 시 접수 비활성, 저장 없이 성공 응답 금지. 오류 로그는 상태 코드·추적 ID만; 본문·인증 토큰·연락처 기록 금지. 예산 한도/오류율/알림 지연/파기 작업 실패 경보를 운영자에게 제공한다.

## 6. 검증과 개발 미리보기

재검증: 서버 테스트 7개 통과, JS 문법 확인, Netlify TOML 파싱, 기존 보호 대상 파일 불변 확인. 브라우저 검증은 양 언어 360/390/768/1440px, FAQ 키보드, 언어 전환 후 입력/오류문 유지, URL 언어 재로드, 두 양식 필수 동의/실패/재시도/성공, 홈페이지 메뉴를 포함한다. 접수 응답은 모의 처리하며 실저장 검증이 아니다. 테스트 스크립트는 외부 브라우저 요청을 차단한다.

로컬 미리보기(저장 기능 없음):

```sh
cd /workspace/vr-meditour-website
python -m http.server 8080 --bind 127.0.0.1
```

- http://127.0.0.1:8080/study-korea/?lang=ko
- http://127.0.0.1:8080/study-korea/?lang=vi

위 주소는 서버가 실행되는 컴퓨터에서만 접근한다. 원격 클라우드 작업 공간은 승인된 포트 전달 또는 저장소를 로컬에 내려받아 실행해야 한다. 정적 서버는 Netlify 함수를 실행하지 않아 설정 API가 404가 되지만 페이지는 안전하게 접수 비활성 상태를 유지한다. 서버리스 실동작 테스트는 별도 격리된 테스트 환경에서 수행해야 한다.

자동 검증: `node tests/study-korea/inquiry.test.cjs`; 로컬 서버 실행 후 Python Playwright/Chromium이 설치된 환경에서 `python tests/study-korea/browser.py`. 미리보기 PNG 4개는 `docs/study-korea-previews/`에 있으며 실제 데이터가 없는 기본 비활성 화면이다. GitHub 브랜치 URL은 소스 코드 링크이며 배포 URL이 아니다.
